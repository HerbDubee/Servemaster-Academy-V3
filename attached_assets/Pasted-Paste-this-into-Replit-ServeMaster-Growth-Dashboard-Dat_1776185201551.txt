# ServeMaster Growth Dashboard - Data Schema and Backend Endpoints Brief

Build the **backend/data layer** for the internal ServeMaster Growth Dashboard.

This brief is only for:
- data schema
- ingestion/storage structure
- backend endpoints
- sync/import contracts

This is an **internal analytics backend**, not customer-facing.

---

## Goal

Create a backend that can combine:
- **GA4 attribution + conversion data**
- **Contentsquare behavior + friction data**
- **campaign metadata from ServeMaster lanes**

The backend should support:
- dashboard views
- weekly reporting
- filtering by source/lane/campaign/platform/language/country
- future automation and recommendation logic

---

# 1) Core Design Principle

Use a **normalized internal analytics schema** with three layers:

1. **Campaign metadata**
2. **Traffic/conversion metrics**
3. **Behavior/friction metrics**

GA4 and Contentsquare should remain external source systems.
The dashboard backend should normalize them into a ServeMaster-friendly internal structure.

---

# 2) Recommended Data Model

## A. campaigns
One row per campaign family.

Fields:
- `id`
- `campaign_key`
- `campaign_name`
- `campaign_type`
  - examples: `social`, `email`, `article`, `partner`, `affiliate`, `lead_magnet`
- `theme`
- `lane`
- `default_language`
- `start_date`
- `end_date`
- `status`
- `notes`
- `created_at`
- `updated_at`

Example:
- `manager_coaching_2026_04`
- `special_occasion_service_2026_04`

# 5) Backend Endpoint Requirements

## A. Summary endpoints

### GET `/api/dashboard/summary`
Return executive summary for selected date range.

Query params:
- `startDate`
- `endDate`
- optional filters:
  - `lane`
  - `platform`
  - `language`
  - `country`
  - `campaign`

- total_sessions
- engaged_sessions
- sign_up_starts
- sign_up_completions
- pricing_views
- team_plan_views
- trial_intent_count
- top_source
- top_campaign
- top_asset

## C. Import / sync endpoints

### POST `/api/import/ga4`
Ingest GA4 aggregated export or API-normalized payload.

Accepted input:
- JSON preferred
- CSV optional

Should write to:
- `traffic_metrics_daily`
- `conversion_metrics_daily`

---

### POST `/api/import/contentsquare`
Ingest Contentsquare summary export or API-normalized payload.

Should write to:
- `page_behavior_daily`
- `friction_findings`

---

### POST `/api/import/campaign-assets`
Ingest campaign metadata from shared-memory, manual ops logs, or operator upload.

Should write to:
- `campaigns`
- `campaign_assets`

---

### POST `/api/import/weekly-snapshot/rebuild`
Recompute weekly snapshot tables.

# 9) Recommendation Engine Hooks
Do not build full AI logic yet, but prepare support for simple rules later.

Suggested future rule inputs:
- best converting source
- highest friction page
- highest traffic / low conversion campaign
- strongest language-market pairing
- strongest LinkedIn article vs LinkedIn post performance

Possible future table:
- `recommendation_runs`
- `recommendations`

Not required for MVP.

# 10) Business Rules to Preserve
- GA4 is source of truth for attribution and conversion
- Contentsquare is source of truth for behavior and friction
- LinkedIn posts and LinkedIn articles must be reported separately
- social cadence target is 2 posts per platform per day
- email target is 5 emails per lane
- LinkedIn articles are an active lane
- email may run in English, French, or Spanish depending on market/language fit
- do not fabricate missing metrics
- clearly label imported/manual sections where needed
